# UX Architecture

## 운영자 흐름

1. 이름과 사이트 주소를 입력한다.
2. FAQ를 붙여넣거나 샘플로 시작한다.
3. 미리보기에서 직접 질문한다.
4. 색상과 문구를 다듬는다.
5. 허용 도메인을 넣고 코드를 복사한다.
6. "shop.example.com에서 방금 감지됨"으로 설치를 확인한다.
7. 이후에는 문의 탭에서 일한다.

## 방문자 흐름

위젯을 열고 시작 질문 또는 직접 입력으로 묻는다. 출처가 달린 답변을 확인한다. 답을 찾지 못하면 그 자리에서 문의 폼으로 이어진다.

## 화면

| 화면 | 판단 | 이유 |
|---|---|---|
| 로그인 + 데모 시작 | 유지 | 평가자가 가입 없이 체험해야 함 |
| 챗봇 생성 | 유지 | 첫 설정 흐름, 3단계 |
| 문의 탭 | 유지, 기본 화면 | 대화 내역과 미해결 문의를 하나의 목록·상세로 통합 |
| 지식 탭 | 유지 | 운영자가 가장 자주 고치는 곳 |
| 위젯 탭 | 유지 | 좌측 설정, 우측 실제 위젯 미리보기 |
| 설치 탭 | 유지 | 코드, 도메인, CSP 안내, 설치 감지, 데이터 보존 |
| 데모 쇼핑몰 | 유지, 별도 배포 | 외부 설치의 증거 |
| 관리자 메인 대시보드 | 제외 | 봇이 하나면 문의 탭으로 직행, 여러 개면 단순 목록 |
| 통계 화면 | 제외 | 운영자의 다음 행동으로 이어지지 않음 |
| 공개 랜딩 페이지 | 제외 | 포트폴리오 케이스 스터디가 대신함 |

## 주요 인터랙션

- 색상을 바꾸면 실제 위젯이 즉시 바뀐다. 저장 전에는 미리보기에만 적용된다.
- "답하지 못함" 대화에서 FAQ로 추가를 누르면 질문이 채워진 편집기가 열린다. 저장 후 바로 재질문할 수 있다.
- 차단된 도메인 요청이 감지되면 설치 탭에 표시하고 클릭 한 번으로 허용한다.
